# v0.1.21 在线更新签名缺失

- 任务名称：发布 v0.1.21 并监控打包
- 日期：2026-09-21
- 状态：待外部配置处理
- 负责人：AI
- 关联文件：`.github/workflows/release.yml`、GitHub Release `v0.1.21`、`latest.json`

## 事实

- GitHub Actions 运行 `35553661375` 已成功完成 Windows x64、macOS x64、macOS aarch64 构建及 Release 汇总。
- `v0.1.21` Release 已上传 Windows MSI、NSIS 安装包、便携包，以及两种 macOS 的 DMG 和便携包，共 7 个安装资产和 `latest.json`。
- 发布产物中没有任何 `.sig` 文件。
- 已下载并检查 `latest.json`：版本为 `v0.1.21`，但 `platforms` 为 `{}`。
- `.github/workflows/release.yml` 只会为与 `.sig` 同名的资产写入更新平台记录；因此缺失签名时汇总作业仍成功，但会生成空清单。

## 影响

- 用户可手动下载安装本次 Release 的 Windows 和 macOS 安装包。
- 桌面端 Tauri Updater 无法从该空清单找到任何平台更新，不应将在线更新视为验证成功。

## 后续处理

- 需要仓库管理员在 GitHub Actions Secrets 中配置有效的 `TAURI_SIGNING_PRIVATE_KEY`，如私钥受密码保护还需配置 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。
- 配置完成后，应以递增版本重新构建和发布，不得复用 `v0.1.21` 标签。
- 后续发布应在汇总工作流中强制校验 Windows、macOS x64 和 macOS aarch64 签名及 `latest.json.platforms`，防止空更新清单被发布。
