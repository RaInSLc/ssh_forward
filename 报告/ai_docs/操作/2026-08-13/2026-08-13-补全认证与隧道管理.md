## 执行记录

1. 用户报告 GUI 缺少密码保存方式，且新建 Tunnel 后无法启动或编辑；截图确认当前 Host 表单只提供私钥路径输入。
2. 已检查实现：认证模型只包含 SSH Agent 和私钥；配置中已有 `credential_id` 预留字段但未使用；GUI 的启动按钮被明确禁用，Core 仅有一次性前台启动 API，未提供运行时注册表或编辑 API。
3. 决定采用 Windows Credential Manager 保存密码、配置只保存凭据 ID，并新增 GUI 进程内 Tunnel 运行时管理。密码不会进入配置、命令行、日志或归档文档。
4. 已扩展认证模型为 SSH Agent、私钥和密码三种类型；密码模式要求非空 `credential_id`。已新增 Windows Credential Manager 读写逻辑，凭据目标名采用应用私有前缀。
5. 已实现 Host 与 Tunnel 的原子编辑、GUI 内进程注册表、Tunnel 启动/停止及子进程退出状态检测。密码认证通过 OpenSSH `SSH_ASKPASS` 临时脚本从进程环境读取，不作为 SSH 命令行参数传递。
6. 已更新 GUI：认证选择、密码输入说明、Host/Tunnel 编辑、真实启动/停止、错误文本和周期状态刷新均已接入。
7. 已新增密码认证配置测试；Rust workspace 测试和严格 Clippy、TypeScript 检查及前端生产构建均已通过。
8. 已补充 OpenSSH 子进程退出探测、停止已退出子进程的安全处理及每个密码 Tunnel 独立的临时 askpass 脚本，避免多个 Tunnel 互相删除脚本。
9. 已执行 Tauri Release Build 并生成 `target/release/ssh-forward-desktop.exe`。独立启动检查通过，程序启动时不依赖本地 1420 Vite 端口；测试窗口已主动停止。
