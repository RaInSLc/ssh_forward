# 实现 V0.1 CLI 核心

- 任务名称：实现 V0.1 CLI 核心
- 日期：2026-08-13
- 状态：已完成
- 负责人：AI
- 关联文件：`报告/ai_docs/方案/初步设计.md`、`Cargo.toml`、`crates/`、`apps/cli/`、`schemas/config-v1.schema.json`、`README.md`

## 目标

根据初步设计文档的第一版开发顺序，创建 Rust workspace，并交付可运行的命令行核心：严格 JSON 配置、Host 与 Local Tunnel 的增删查、配置校验、OpenSSH 本地转发命令构建与启动控制。

## 范围

- 创建 `ssh-forward-config`、`ssh-forward-ssh`、`ssh-forward-core` 和 CLI 四个 workspace 成员。
- 使用 OpenSSH 兼容后端实现本地 `-L` 转发；默认绑定 `127.0.0.1`，默认启用严格 Host Key 检查。
- 以项目内 `--config` 参数指定配置文件；默认配置路径为当前目录的 `config.json`，避免本次实现写入用户配置目录。
- 提供 JSON Schema、示例配置、README 及单元测试。

## 不在本次范围

- Tauri GUI、系统托盘、嵌入式 SSH、系统凭据库、密码认证、远程或动态转发、ProxyJump、守护进程、配置迁移和跨进程运行状态管理。
- 真实 SSH 主机连接测试；不会读取、修改或记录任何用户 SSH 私钥与凭据。

## 前提与风险

- 本机已发现 Rust 1.96 和 Windows OpenSSH 9.5；构建所需 crate 将使用项目目录内的 Cargo 缓存。
- OpenSSH 子进程仅能在当前 CLI 进程存活期间维持；完整的连接复用、重连和后台运行将留待后续核心运行时实现。
- 默认 JSON 配置不保存密码或私钥内容，仅可保存私钥路径或 SSH Agent 认证类型。

## 实施与验证计划

1. 创建计划后初始化 workspace 与配置模型，完成原子配置写入和语义校验。
2. 实现 OpenSSH 参数构建、端口预检查以及 CLI CRUD、validate、start 命令。
3. 添加 Schema、示例与使用说明。
4. 在项目内设置 Cargo 缓存后执行格式化、单元测试、Clippy 和 CLI 冒烟检查。
