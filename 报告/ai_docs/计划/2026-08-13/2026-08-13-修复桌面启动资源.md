## 目标

修复直接启动桌面端 Debug 可执行文件时访问未启动的 Vite 开发服务器的问题，交付加载本地 `dist` 资源的可直接运行桌面端构建产物，并更正文档说明。

## 已知原因

现有 Tauri 配置包含 `devUrl: http://localhost:1420`。通过普通 Cargo Debug 构建运行时，Tauri 选择该开发 URL；若 Vite 未运行，WebView2 显示 `ERR_CONNECTION_REFUSED`。

## 实施范围

- 使用项目内 Tauri CLI 构建生产资源模式的桌面端，不启动持续的 Vite 开发服务。
- 验证生成的可执行程序加载本地前端资源。
- 更新 README，明确 `tauri.cmd dev` 用于热更新开发；独立运行必须使用 Tauri Build 产物，不能使用普通 `cargo build` 的 Debug 可执行文件。

## 风险与验证

- Tauri Build 会生成项目内构建产物，可能需要较长时间，但不涉及外部 SSH 连接或凭据。
- 验证会检查构建输出、配置资源路径和程序启动行为；不读取或修改用户的 SSH 配置与凭据。
