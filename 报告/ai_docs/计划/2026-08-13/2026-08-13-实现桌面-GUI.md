# 实现桌面 GUI

- 任务名称：实现桌面 GUI
- 日期：2026-08-13
- 状态：已完成
- 负责人：AI
- 关联文件：`Cargo.toml`、`apps/desktop/`、`crates/ssh-forward-core/`、`crates/ssh-forward-config/`、`README.md`

## 目标

在现有 Rust CLI 核心上实现 Tauri 2 与 React/TypeScript 桌面端，为配置管理提供图形界面，并复用现有 Core 的 Host、Local Tunnel 和配置校验逻辑。

## 范围

- 创建 `apps/desktop` 前端及 `src-tauri` 后端，作为 Cargo workspace 成员。
- 展示并管理当前项目目录的 `config.json`：配置路径、校验、Host 列表、Tunnel 列表、新增与删除。
- 默认仅允许 `127.0.0.1` 和 `::1` 本地绑定，沿用核心的安全校验。
- 为 V0.1 提供清晰的连接状态占位与功能边界提示，不伪造实时连接状态。

## 不在范围

- 自动重连、连接复用、后台守护进程、系统托盘、Host Key 交互、凭据库、远程/动态转发、自动选择端口和完整 Tunnel 启停生命周期。
- 未经授权的真实 SSH 主机连接或凭据读取。

## 前提与风险

- 本机有 Node 22、npm 10 与 Rust 1.96，但没有全局 Tauri CLI；使用项目本地 npm 依赖与 Cargo crate 构建。
- Tauri Windows 开发构建可能依赖 WebView2 与 Visual Studio C++ 工具链；若环境缺失，将记录具体阻塞。
- GUI 与 CLI 默认都使用工作目录 `config.json`，同时提供显式配置路径输入；并发写入协调留待后续运行时实现。

## 实施与验证计划

1. 创建本计划和操作归档后，新增桌面端 manifest、Tauri 命令层及前端源文件。
2. 实现配置加载、校验、Host/Tunnel 创建和删除 IPC 命令，复用 Core 与 Config crate。
3. 实现响应式 React 界面与表单错误反馈。
4. 安装仅位于项目内的 npm 依赖，并执行前端类型检查、生产构建、Rust 格式化、测试、Clippy 和 Tauri 检查。
